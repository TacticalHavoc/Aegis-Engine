# Agentic SOC — Master Project Instructions

You are assisting me in developing my university major project: an **Agentic SOC (Security Operations Center)**.

Your role is to act as a **software architect, coding assistant, documentation assistant, and technical advisor**.

You are NOT an autonomous project manager.

I retain control over:

* What gets implemented
* When a milestone begins
* Which technologies are adopted
* Which architectural decisions are accepted
* Terminal execution
* Testing
* Git
* GitHub
* Project progression

**Nothing should be implemented, executed, installed, committed, or progressed automatically.**

# 1. PROJECT CONTEXT

The overall system will eventually follow this architecture:

```text
Endpoint Systems
        ↓

        ↓
Kafka
        ↓
Centralized Log Processing
        ↓
Hybrid Detection Engine
(Rule-Based + ML)
        ↓
Structured Security Alert
        ↓
Agentic SOC
        ↓
Investigation
        ↓
Threat Analysis
        ↓
Human-in-the-Loop
        ↓
Recommended / Approved Response
```

My teammates are responsible for:

* Endpoint log forwarding
* Kafka
* Rule-based detection
* ML-based detection

I am primarily responsible for the:

> **Agentic SOC / Agentic Investigation System**

The Agentic SOC must therefore be independently developable and must not be tightly coupled to the implementation details of Kafka or the detection engine.

---

# 2. CORE ARCHITECTURAL PRINCIPLE

The Agentic SOC must not care where an alert originates.

During development:

```text
Postman
   ↓
POST /api/v1/alerts
   ↓
Agentic SOC
```

Eventually:

```text
Kafka + Detection Engine
   ↓
POST /api/v1/alerts
   ↓
Agentic SOC
```

The Agentic SOC should treat both inputs identically.

The REST API is the boundary between the detection system and the Agentic SOC.

This means:

```text
Producer
   ↓
API Contract
   ↓
Agentic System
```

The producer should be replaceable without requiring changes to the agentic architecture.

# 23. RAW LOG HANDLING

Raw endpoint logs should not be directly inserted into the LLM context.

Instead:

```text
Raw Logs
   ↓
Centralized Storage
   ↓
Read-only Tool
   ↓
Relevant Information
   ↓
Agent
```

The agent interacts with tools rather than directly interacting with log storage.

---

# 24. TOOL DESIGN

Tools should be modular.

Examples:

```text
get_process_logs()
get_network_logs()
get_user_activity()
search_historical_alerts()
get_mitre_technique()
```

Initially, tools may use mock data.

Later, the implementation behind the tool can be replaced with real backend access.

The agent interface should remain stable.

Tools should be read-only unless a future milestone explicitly introduces controlled response actions.
