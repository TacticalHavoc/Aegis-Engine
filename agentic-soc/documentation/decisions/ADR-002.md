# ADR-002: Read-Only Tool Pattern for SOC Investigation Agents

Status: Accepted

## Context

Security Operations Center (SOC) agents require access to extensive log telemetry (process events, network flows, authentication records) to investigate security alerts. 

Passing entire raw log collections directly into LLM prompts/contexts is prohibitive due to context size limits, financial costs, noise-to-signal ratios, and security risks (accidental leakage or modification of log data).

We needed to decide how the Investigation Agent accesses backend telemetry stores.

## Decision

We decided to mandate a strict **Read-Only Tool Abstraction Pattern** for all agent data access.

Agents interact with log telemetry exclusively through dedicated, typed tool functions (e.g., `get_process_logs`, `get_network_logs`). The tools enforce parameter filtering (host, time window, process name) and return structured Pydantic models (`ProcessEvent`).

## Alternatives Considered

1. **Direct SQL / Query Execution by Agent**:
   - Allowing the agent to generate and execute direct SQL or Elasticsearch queries against the datastore.
   - *Drawbacks*: High risk of query injection, syntax hallucination, non-deterministic performance degradation, and accidental privilege escalation.
2. **Bulk Log Context Insertion**:
   - Ingesting raw logs into the agent's initial prompt context alongside the alert.
   - *Drawbacks*: Quickly exhausts context windows, high token cost, and distracts reasoning with irrelevant background noise.

## Rationale

- **Security & Non-Destructiveness**: Read-only tools guarantee that autonomous agents cannot tamper with, delete, or alter log records during investigation.
- **Backend Decoupling**: Agents remain unaware of whether data originates from mock arrays, ClickHouse, Elasticsearch, or OpenSearch. The backend can be migrated without modifying agent logic.
- **Targeted Retrieval**: Enforces bounded time windows and host scoping, keeping evidence extraction focused and deterministic.

## Consequences

- New telemetry data sources require explicit tool definitions and schemas before agents can access them.
- Tool schemas must be kept synchronized with downstream investigation models.
