# ADR-003: Multi-Agent Flagged Log Incident Analysis Architecture

**Status**: Accepted  
**Date**: 2026-10-06  

---

## Context

The Agentic SOC ingests incident signals from an upstream **Kafka Ingestion + Rule Engine + ML Detection Pipeline**. 

When the upstream detection pipeline identifies anomalous endpoint or network activity, it outputs a discrete **Incident Bundle** containing the alert metadata and a collection of **Flagged Log Events** (processes, network connections, file access, authentication events, DNS queries).

We needed an architecture that:
1. Ingests these flagged log bundles directly.
2. Coordinates multi-agent analysis (Lead Investigator $\rightarrow$ Threat Analyst $\rightarrow$ Remediation Advisor) to synthesize a comprehensive incident narrative, attack timeline, and MITRE ATT&CK mapping.
3. Operates natively with standard, reliable LLM clients (Google Gemini, OpenAI) and provides a deterministic heuristic fallback for offline/CI environments without framework lock-in or runtime version incompatibilities.

---

## Decision

We implemented the **`IncidentAnalyzer`** Multi-Agent Engine ([`app/agents/incident_analyzer.py`](file:///home/astute/Projects/AgenticSOC/app/agents/incident_analyzer.py)) and exposed the dedicated analysis endpoint:

```http
POST /api/v1/incidents/analyze
```

### Key Architectural Elements:
- **`FlaggedLog` & `Incident` Schemas** ([`app/models/incident.py`](file:///home/astute/Projects/AgenticSOC/app/models/incident.py)): Standardized contracts for receiving the upstream Kafka/ML detection output.
- **`IncidentReport` Schema**: Structured output format detailing `verdict`, `confidence`, `severity`, `executive_summary`, `root_cause`, `attack_timeline`, `mitre_attack`, `affected_entities` (IOCs), and `recommended_actions`.
- **Multi-Agent Collaborative Roles**:
  1. *Investigator Agent*: Constructs the attack timeline and traces the process-to-network execution chain.
  2. *Threat Analyst Agent*: Evaluates severity, assesses blast radius, and maps behaviors to MITRE ATT&CK.
  3. *Remediation Advisor*: Formulates concrete host containment, process termination, and IOC blocking instructions.
- **Dual Execution Engine**:
  - *Live Mode*: Direct structured JSON generation via Gemini (`gemini-2.0-flash`) or OpenAI (`gpt-4o`).
  - *Deterministic Engine*: Built-in correlation heuristics for offline/test environments.

---

## Alternatives Considered

1. **Monolithic Prompting over Raw Logs**:
   - *Rejected*: Ingesting raw, unfiltered logs into a single prompt is cost-prohibitive and causes hallucination. Filtering via the upstream Kafka/ML engine before agent synthesis is far more scalable.
2. **Third-Party Agent Wrappers (PydanticAI)**:
   - *Rejected*: Experimental wrappers introduced type resolution bugs under newer Python runtimes. A direct, lightweight agent engine provides higher stability and zero external framework lock-in.

---

## Consequences

- **Benefits**:
  - Directly aligns with the user's Kafka + ML pipeline architecture.
  - End-to-end incident analysis returning complete executive summaries, timelines, MITRE techniques, and actionable remediation steps.
  - Robust, testable offline execution with zero API keys required in test suites.
